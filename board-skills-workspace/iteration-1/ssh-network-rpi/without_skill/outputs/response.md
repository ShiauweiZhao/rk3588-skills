# 树莓派 4B SSH 连接诊断方案

## 基本信息

- 设备: 树莓派 4B
- IP: 192.168.0.50
- 用户名: pi
- 密码: raspberry
- 症状: 之前正常,今天突然无法连接

## 诊断步骤

### 第一步: 检查网络连通性

先确认板子是否在线,从最基础的网络层开始排查。

```bash
# 1. 检查本机网络是否正常
ping 192.168.0.50 -c 4

# 2. 查看本机网络接口,确认你也在同一网段
ifconfig | grep "inet "
# 或
ip addr show
```

**预期判断:**
- 如果 ping 通了 -> 网络层正常,问题在 SSH 服务层,跳到第三步
- 如果 ping 不通 -> 网络层问题,继续第二步

### 第二步: 网络层排查 (ping 不通时)

```bash
# 1. 检查是否在同一个子网
# 你的电脑 IP 也应该是 192.168.0.x 网段

# 2. 扫描局域网,看看树莓派是否还在网络上
arp -a | grep 192.168.0

# 3. 用 nmap 扫描整个网段,查找树莓派
nmap -sn 192.168.0.0/24

# 4. 检查路由器 DHCP 分配表
# (通常在路由器管理页面 192.168.0.1 可以看到)
```

**可能原因:**
- 树莓派没通电 / 电源线松了
- IP 地址变了 (路由器重新分配了 DHCP)
- 网线没插好 / WiFi 断了
- SD 卡损坏导致系统没启动

**应对方法:**
- 检查树莓派电源指示灯 (红灯常亮 = 供电正常)
- 检查活动指示灯 (绿灯闪烁 = SD 卡在读)
- 如果怀疑 IP 变了,用 nmap 扫描找到新 IP
- 如果有 HDMI 显示器,接上看看有没有画面

### 第三步: SSH 服务层排查 (ping 通但连不上)

```bash
# 1. 测试 SSH 端口是否开放
nc -zv 192.168.0.50 22
# 或
telnet 192.168.0.50 22

# 2. 尝试 SSH 连接,带详细日志
ssh -vvv pi@192.168.0.50

# 3. 如果端口不通,尝试其他常用端口
nc -zv 192.168.0.50 22
nc -zv 192.168.0.50 80
nc -zv 192.168.0.50 443
```

**根据 SSH 报错判断:**

| 报错信息 | 可能原因 | 解决方法 |
|---------|---------|---------|
| `Connection refused` | SSH 服务未运行或端口被改 | 需要物理访问重启 sshd |
| `Connection timed out` | 防火墙阻断或网络不通 | 检查防火墙规则 |
| `Host key verification failed` | 板子重装系统后 host key 变了 | `ssh-keygen -R 192.168.0.50` 删除旧 key |
| `Permission denied` | 密码错误或用户被禁用 | 确认密码,检查是否被暴力锁定 |
| `Connection reset by peer` | 服务崩溃或被踢出 | 重启 SSH 服务 |

### 第四步: 已知主机冲突处理

如果之前连接过该 IP,可能是 known_hosts 缓存问题:

```bash
# 删除旧的 host key
ssh-keygen -R 192.168.0.50

# 然后重新连接
ssh pi@192.168.0.50
```

### 第五步: 高级排查 (需要物理访问或串口)

如果以上远程方法都无法解决,需要物理接触板子:

```bash
# 接上 HDMI 显示器和键盘后执行:

# 1. 检查 SSH 服务状态
sudo systemctl status sshd
# 或
sudo service ssh status

# 2. 如果服务停止了,启动它
sudo systemctl start sshd
sudo systemctl enable sshd  # 设置开机自启

# 3. 检查 SSH 配置是否被修改
cat /etc/ssh/sshd_config | grep -v "^#" | grep -v "^$"

# 4. 检查磁盘空间 (满了会导致各种奇怪问题)
df -h

# 5. 查看系统日志
journalctl -u sshd --since "today"
dmesg | tail -50
/var/log/auth.log  # 认证日志

# 6. 检查网络配置
ip addr show
ip route show
cat /etc/dhcpcd.conf  # 静态 IP 配置

# 7. 检查防火墙
sudo iptables -L -n
sudo ufw status
```

## 常见原因速查

按概率从高到低排列:

1. **SD 卡文件系统损坏** -- 树莓派最常见的问题,突然断电或不正常关机导致。表现为绿灯不正常闪烁或无法启动。
2. **DHCP 分配的 IP 变了** -- 路由器重启后可能重新分配 IP。建议设置静态 IP。
3. **SSH 服务崩溃/未启动** -- 系统更新后偶尔发生。
4. **电源供电不足** -- 树莓派 4B 对电源敏感,换电源线/适配器试试。
5. **known_hosts 缓存冲突** -- 如果你有多块板子用了同一个 IP。
6. **密码被暴力锁定** -- 如果开了外网端口,可能被攻击了。

## 建议操作顺序

1. 先 `ping 192.168.0.50` 看通不通
2. 不通的话,去路由器管理页面看看 DHCP 列表里还有没有这个设备
3. 不确定的话,`nmap -sn 192.168.0.0/24` 全网扫描找新 IP
4. ping 通但 SSH 不行的话,`ssh -vvv pi@192.168.0.50` 看详细报错
5. 都不行的话,接 HDMI 显示器 + 键盘物理排查

---

> 注意: 以上所有命令都需要在你的电脑 (非树莓派) 上执行。标注了"物理访问"的部分需要直接操作树莓派本体。
